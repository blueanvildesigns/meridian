Pure modules again (`webapp/src/storage/`, `webapp/src/cities/`), plus the data pipeline. Nothing in the app imports them until M3 and M4, so the live bundle is unchanged.

| ID | Decision | Source | Status |

| M2-1 | **Stored city schema** (refines D2). Three kinds: `local` (My Local Time), `zone` (bare IANA zone) and `place` (`geonameId`, `name`, `countryCode`, `country`, optional `region`, `lat`, `lon`, `zone`). A rename is an optional `customName`, not a `name` + `originalName` pair: clearing a rename deletes it, which gives D15's "empty rename reverts" and D14's "keep a custom name only if renamed" for free. | M2-2 | **Storage rules** (refines D19). Availability is tested with a real probe write, because some browsers expose `localStorage` but refuse writes. A bad entry is dropped on its own; the rest of the list survives. Duplicates are dropped per D3, first one wins. Unreadable or partly unreadable data is copied to `meridian.backup` (one slot; a later problem replaces it) before anything can overwrite it. **If that copy can't be made, the app runs in memory rather than risk losing the only copy.** Data from a newer schema (an old tab left open across a deploy) is read as well as possible but never written. Loading never writes; the first change does. The migration registry is empty at v1, and a pre-migration copy is backed up (best effort). | M2-3 | **City subset** (refines D18): GeoNames `cities15000` (every place over 15,000 people, plus capitals), minus historical, abandoned and destroyed places (`PPLH`, `PPLQ`, `PPLW`, `PPLCH`).

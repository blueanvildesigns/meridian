## M2: storage and city data (2026-11-18)

Pure modules again (`webapp/src/storage/`, `webapp/src/cities/`), plus the data pipeline. Nothing in the app imports them until M3 and M4, so the live bundle is unchanged.

| ID | Decision | Source | Status |
|---|---|---|---|
| M2-1 | **Stored city schema** (refines D2). Three kinds: `local` (My Local Time), `zone` (bare IANA zone) and `place` (`geonameId`, `name`, `countryCode`, `country`, optional `region`, `lat`, `lon`, `zone`). A rename is an optional `customName`, not a `name` + `originalName` pair: clearing a rename deletes it, which gives D15's "empty rename reverts" and D14's "keep a custom name only if renamed" for free. Settings `{timeFormat, appearance}` share the same `meridian` key, which the M0 theme boot script already reads. | Default | Confirmed (owner, R-13) |
| M2-2 | **Storage rules** (refines D19). Availability is tested with a real probe write, because some browsers expose `localStorage` but refuse writes. A bad entry is dropped on its own; the rest of the list survives. Duplicates are dropped per D3, first one wins. Unreadable or partly unreadable data is copied to `meridian.backup` (one slot; a later problem replaces it) before anything can overwrite it. **If that copy can't be made, the app runs in memory rather than risk losing the only copy.** Data from a newer schema (an old tab left open across a deploy) is read as well as possible but never written. Loading never writes; the first change does. The migration registry is empty at v1, and a pre-migration copy is backed up (best effort). Unrecognised zones are kept, so they get spec 4.6's "Choose a zone" card instead of vanishing. Not done yet: syncing between open tabs (the `storage` event); M3 can add it. | Default | Confirmed (owner, R-13) |
| M2-3 | **City subset** (refines D18): built from GeoNames `cities15000`, minus historical, abandoned and destroyed places (`PPLH`, `PPLQ`, `PPLW`, `PPLCH`), then cut to **places of 50,000 people or more, every capital, and each zone's representative** (owner decision, M2-10). That's **12,481 places in 356 zones and 244 countries**, export of 2026-11-18. Keeping the representatives (23 places under 50,000) means no zone loses its sunrise location or its place in search. City sections that people search for, such as Kowloon, Shibuya and Navi Mumbai (`PPLX`), stay in. Places are stored in population order, so file order is the ranking and population isn't shipped.

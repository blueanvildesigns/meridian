### M0 hosting additions (2026-11-18, after `docs/hosting-plan.md` and the addendum)

| ID | Decision | Source | Status |

| M0-12 | `firebase.json` lives at the **repo root** with `public: webapp/dist`. `firebase init hosting:github` writes workflows under `.github/` relative to where it runs, and GitHub only reads the root `.github/`. | Found | Confirmed |
| M0-13 | **Header rules never overlap on a header key.** Firebase applies rules in order but doesn't document which wins on a conflict. Layout: security headers plus `X-Robots-Tag` on `**`; `Cache-Control: immutable` on `/assets/**`; `no-cache` on `**/*.html` and on dot-less paths (regex `^/[^.]*$`: `/` and SPA routes). Other root files (`favicon.svg`, `robots.txt`) keep Firebase's default caching. Enforced by `scripts/firebaseHosting.ts`, which throws on overlap, plus its unit tests. | Found | Confirmed |
| M0-14 | CSP: same-origin only. The inline theme script is allowed by its SHA-256 hash; there's no `unsafe-inline` or `unsafe-eval`. A unit test fails if the hash in `firebase.json` doesn't match `THEME_BOOT_SCRIPT`. E2E serves the production build through `scripts/serve-dist.ts` (applies `firebase.json` headers and rewrites) and fails on any CSP violation or console error. I checked that a wrong hash makes the e2e test fail. React's `style` props set styles through the CSSOM, which CSP doesn't block, so `style-src 'self'` holds. | Default | Confirmed |

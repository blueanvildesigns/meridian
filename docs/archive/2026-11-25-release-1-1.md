# Decision: Release 1.1, Send a moment (M8 to M10)

Date: 2026-11-25
Source: design interview, round 1 after launch, plus mockup review the same evening. Roadmap: `docs/roadmap.md` (Release 1.1). Mockups: the Artifacts canvas "Meridian Web: Design Canvas", rows "Send a moment: Copy as text (M8)", "Add to calendar (M9)" and "DST heads-up (M10)" (boards `SendLive`, `SendJump`, `CopyTextOutput`, `CalendarDialog`, `CalendarDialogPhone`, `DstLive`, `DstLiveDark`, `DstJump`, `DstPhone`). The canvas is not in this repo; values below that are not pinned here should be confirmed against it. Refines spec 4.1 and 4.3. No stored-data change in this release.

## Decisions

### M8: Copy as text

1. **Layout:** one line per city, one city per line.
2. **Date on every line (Option A).** Each line reads `New York: Tue, Mar 30, 9:00 AM EDT`. There is no separate date header.
3. **Link:** the text ends with a Meridian link for the moment, as the last line, after a blank line.
4. **Names:** the names as shown on the person's cards, renames included. (The link still follows M5-1 and never carries renames.)
5. **My Local Time** is written as `My Local Time (America/Chicago)`, with the device's zone in brackets, as drawn.
6. **Where:** the Jump banner and live mode.
7. **Live-mode link:** a link to the instant copied, which opens as a Jump to that moment. It carries no city name (`#at=…&ref=America/Chicago`), because My Local Time means a zone, not a place (M5-1). The recipient sees a fixed time, not a live clock.
8. **Entry points:** a secondary "Copy as text" button beside "Jump to a time" in live mode; in the Jump banner, between Copy link and Add to calendar. Toast: "Copied as text".

### M9: Add to calendar

9. **Jump mode only.** A calendar event needs a chosen time, so there is no entry point in live mode.
10. **Dialog fields:** title (starts empty, focused) and duration (required, no default, presets 15 min, 30 min, 45 min, 1 hour, 1.5 hours, 2 hours, plus "Custom…"). Every action stays disabled until a duration is chosen. Once chosen, the dialog shows the end time in the reference city's zone and in the person's own calendar zone.
11. **Anchor zone:** the Jump reference city's zone.
12. **Outputs, in three tiers (as drawn on `CalendarDialog`):**
    - **Download .ics file** (main action). Works with Outlook for desktop, Apple Calendar and most other calendar apps.
    - **Open in a web calendar:** Google Calendar, **Outlook.com** (personal accounts) and **Microsoft 365** (work or school accounts). Each opens the provider's compose page in a new tab with the event filled in.
    - Cancel.
13. **Outlook links are best effort.** They are unofficial and have changed before (see open points). Times are sent as UTC (`Z`), never as `+HH:MM` offsets.
14. **Privacy line, as drawn:** the file is made in the browser and goes nowhere; opening Google Calendar or Outlook sends the title and time to Google or Microsoft. Built in the browser; nothing else is sent anywhere.
15. **Phone:** the same dialog as a bottom sheet (`CalendarDialogPhone`), with the web calendar buttons wrapping.

### M10: DST heads-up

16. **Live mode:** a chip on any card whose UTC offset changes within the next 14 days.
17. **Wording (live):** `Clocks change Sun, Mar 14` (the first of two options; the other was `Sun, Mar 14: EST → EDT`).
18. **Design:** amber, with an icon and text, never colour alone. The chip sits between the time row and the card footer. Cards in the same grid row grow to match; cards without a chip keep the extra space.
19. **Jump mode:** flag every city whose offset on the jumped date differs from its offset now, not only cities with a change on the jumped day itself.
20. **Jump banner line.** Because My Local Time's own offset can change, every "difference" line may change even on cards with no chip (for example Kolkata: +11h 30m today, +10h 30m on the jumped date). The Jump banner therefore carries one extra line naming the cities whose clocks differ from today, for example "Clocks differ from today in My Local Time, New York and London." (Owner: keep this solution.)

## Proposed by Claude, not yet confirmed

- Jump-mode chip text: `EDT then · EST today` (drawn on `DstJump`). The live-mode wording was chosen; this one was drawn to match it but not separately confirmed.
- Chip colours, derived (the design spec has no dark-mode warn values): day card chip fill #FFF4D6, text #4A2F00, border #A86F0C; night card chip fill #2E2410, text #F2C078, border #8A6A1E. Checked by hand at about 11.3:1 (day text), 9.2:1 (night text), and 3.2:1 for the night border against the card. They must be added to the contrast test (R-7 says every token pair is checked in both themes). On the softened day cards in dark mode the day chip is used unchanged.
- Copy as text uses the Settings 12/24h format and the browser locale for day and month names, with the zone abbreviation (M1-4).
- Calendar file name `meridian-<yyyy-mm-dd>.ics`. Event times written as UTC instants, with the reference zone's name in the description.
- An empty title is allowed; the dialog should say the event will be untitled. The title placeholder in the mockup is "What is it?".
- A city that changes offset more than once in the window shows one chip, for the first change. "My Local Time" gets the chip too.
- The date and zone in the Jump banner line follow the same wording rules as the existing banner text.

## Open points

- **M10 needs a spike first.** It relies on finding the next zone transition. I haven't confirmed that the Temporal polyfill supports it (for example `getTimeZoneTransition`). If it doesn't, the fallback is scanning offsets day by day. Either way, tests must pass on native Temporal and on the polyfill.
- **M9 needs a CSP check on a preview deploy** that a `blob:` download works under the current same-origin CSP (M0-14). If it doesn't, stop and ask; the fix is a design decision, not a quiet CSP change. Opening the web calendar links is plain link navigation and should not be affected.
- **Outlook web links need testing against both account types**, which cannot be done from the design side. Known from public reports (unconfirmed by me): personal and work accounts use different hosts (`outlook.live.com` and `outlook.office.com`); the path changed in 2023 and broke some links; the mobile apps may not open the compose screen; one report says `+HH:MM` offsets fail for work accounts, which is why times go as UTC. If a link cannot be made to work on a preview, drop that button rather than ship a broken one, and say so.
- **Not drawn:** the "Custom…" duration control (decide: presets only in 1.1, or a minutes field) and an error state for when the `.ics` file cannot be created.
- Phone state for the active Jump banner is still stacked-by-default, as in the Jump decision.
- Whether the live-mode copied link should warn that it freezes the time. Probably not.

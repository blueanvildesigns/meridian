# Decision: Jump

Date: 2026-11-17
Source: design interview, round 6. Mockups: canvas "Meridian Web: Design Canvas", row "Jump: preview a date and time" (`JumpActive`, `JumpPicker`, `JumpPickerGap`, `JumpPickerOverlap`, `JumpPhone`).

## Decisions

1. **Picker:** a popover anchored to the "Jump to a time" button on desktop, a bottom sheet on phones. Fields: "Time is in" (city), Date, Time, a line showing the same moment in UTC, Cancel and Apply. Nothing changes on the grid until Apply.
2. **Reference city:** chosen from a dropdown in the picker (default My Local Time), and also from a "Jump from here" action on each card. The action lives in the card's more-options menu, which is not designed yet.
3. **DST edge cases: explain and let the user choose.**
   - **Skipped time** (e.g. 2:30 AM on Mar 14, 2027 in New York): inline alert says the time doesn't exist and that clocks skip 2:00 to 3:00 AM, with a "Use 3:00 AM instead" button. Apply is disabled until the time is valid.
   - **Repeated time** (e.g. 1:30 AM on Nov 7, 2027 in New York): inline radio group "Which 1:30 AM?" with the two occurrences, EDT (first) and EST (second). The first occurrence is preselected.
4. **Jump state is kept in the URL, with a Copy link button.** The link reopens the same moment. No backend. A reload without the URL returns to live.
5. **Active state:** a banner replaces the LIVE indicator. It says "JUMPED", shows the date and time with the reference city, says clocks are paused, and offers Copy link, Change and Reset to live (the primary action). The reference city's card gets a "Jump reference" tag and a stronger outline. Cards show full dates and the day/night cue for the jumped moment.
6. **Time math requirements** (from the old app's bugs): calendar-day arithmetic in the reference city's zone, never "+24 hours"; instant-based conversion for every card; picking "now" never jumps a day ahead.

## Proposed by Claude, not yet confirmed

- In Jump mode, the relative-day chip compares each city's date with My Local Time's date at the jumped moment ("Same day", "Next day", "Previous day"). The old app compared with today's real date, which gives "+16 days" on every card.
- The Apply-then-update flow (no live preview in the grid while editing).

## Open points

- URL format and contents, for example `?at=<UTC instant>&ref=<IANA zone>`. Decide what happens when the link's reference city is not in the recipient's list.
- Date and time input controls: the mockups use plain text fields; the implementation needs a real date picker and time input that work with the browser locale and with 12h/24h.
- Phone state for an active Jump is not drawn; it follows the desktop banner, stacked.
- Not yet designed: card more-options menu (rename, remove, Jump from here), settings, About page, empty list state, error states, app-wide dark mode.
